# Style Bible

## Voice

Warm, direct, curious, and precise about evidence. Never condescending.

## Accessibility of language

Middle-school-accessible baseline with optional engineering and research depth.

## Analogy rule

Analogies must be explicitly labeled as analogies and must not replace technical meaning.

## Status language

Allowed project-state vocabulary includes: implemented, validated prototype, simulated, requirement, hypothesis, future concept, illustrative, measured, planned, repository-implemented, repository-tested.

Forbidden upgrades:

- planned → implemented
- simulated → deployed
- repository-tested → independently validated

## Diagram grammar

Every labeled object answers: What is it? What does it do? What changes for the person when it works well—or fails?

Color never carries meaning alone. Prefer labels, shapes, and patterns.

## Accessibility

Every figure needs figure ID, caption, alt text, text equivalent, reading order (when complex), source, status, reviewer, version.

## Evidence tone

Prefer honest uncertainty over impressive overclaim.
