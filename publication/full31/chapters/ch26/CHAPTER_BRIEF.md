## Reader promise

Use version control and small development loops to produce reviewable change—portfolio evidence of building, not slogans about being a developer.

## Anchor human moment

A learner changes one behavior, commits with a clear message, and can show what differed—then recovers from a mistake without rewriting history myths.

## Teaching model

`moment → notice → ecosystem → signal → components → Stability Contract → Try/Build → secure/include → career → check → glossary`

Central chain: **Human experience → system → component → code → network → society**

## Measurable outcomes (Explorer → Researcher)

| Pathway | Outcome |
|---|---|
| Explorer | Explain commit / branch / diff in ordinary language. |
| Operator | Read a status/diff and say what will change before running it. |
| Builder | Make a small change with tests or checklist evidence. |
| Engineer | Propose a reviewable PR-sized change with rationale. |
| Researcher | Document reproducibility of the change environment at a SHA. |

## Stability Contract (chapter conditions)

- Working tree understandability (status/diff readable)
- History integrity practices appropriate to collaboration
- Secrets never committed
- Build/test loop runnable on commodity hardware or fixtures

## Security / equity / accessibility (integrated)

Secrets hygiene; accessible CLI/GUI alternatives; no assumption of paid IDEs. Equity: offline tutorial fixtures.
